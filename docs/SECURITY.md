# Security review (2026-10-29)

Scope: Spark AI Hub 0.1.0 as deployed on a DGX Spark. This is a review by the implementer plus automated acceptance
tests; it is **not** an independent audit or penetration test, and the deployment should not be described as
"production-secure" without one. Unresolved items are listed at the end.

## Network exposure

| Item | Status | Evidence |
|---|---|---|
| Published ports | only `127.0.0.1:8080` (Caddy). Postgres, Redis, Ollama, vLLM, ComfyUI, ML worker, engine-manager, backend have **no** published port | `ss -tlnp`; acceptance test 23 probes 16 host:port pairs on the public IP and the Tailscale IP → all closed |
| Docker bypassing ufw | avoided: nothing is published on 0.0.0.0 | — |
| Remote access | Tailscale Serve HTTPS, `(tailnet only)`; **Funnel not enabled** | `tailscale serve status` |
| Internal networks | `data`, `control`, `engines` are `internal: true` (no egress). Engines (incl. vLLM running `trust_remote_code` models) cannot reach the Internet or LAN | compose.yaml |
| Headers | HSTS, X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy; artifacts served with `Content-Security-Policy: sandbox` | test 01 |

Recommendation (not applied, needs tailnet admin): restrict the Spark in Tailscale ACLs to the researchers' devices/users.

## Authentication & sessions

* No self-registration. Users are created by an admin; activation/reset via one-time, expiring links (72 h / 24 h), stored as
  HMAC digests. Passwords: Argon2id (argon2-cffi), policy ≥10 chars, mixed case, digit.
* Sessions: 256-bit random token in an `HttpOnly; Secure; SameSite=Strict` cookie; only the HMAC digest is stored;
  12 h TTL; revocation on password change/deactivation; session list per user.
* CSRF: double-submit token (`sah_csrf` cookie ↔ `X-CSRF-Token` header) required on every unsafe method (test 03d).
* Brute force: Redis rate limits (20/5 min per IP, 10/5 min per username) + account lock 15 min after 8 failures.
* OIDC: not implemented (optional in the brief). Can be added in front (Tailscale identity headers or an OIDC proxy).

## Authorisation

* Server-side RBAC: `admin`, `researcher`, `viewer`. Admin/settings/user/backup/diagnostic endpoints require an
  **interactive admin session** — API keys are never accepted there (test 12, 22).
* Resource-level checks on conversations, datasets, artifacts, experiments, jobs, comparisons, API keys and models.
  Other users' private resources return **404** (no existence leak) (test 04).
* Admins can see and manage all registered models (needed to operate the shared registry) but not researchers' private
  conversations, datasets, artifacts or experiments through the UI/API.
* Model installation by researchers requires admin approval; publishing to everyone, pinning and remote-code approval
  are admin-only.

## API keys

`sah-` + 256-bit random; only an HMAC-SHA256 digest is stored; shown once; scopes `inference` / `jobs`; expiry (default
90 d), revocation, per-key rpm and monthly token quota; usage attributed per key. No master key is ever exposed: the
gateway authenticates against the hub DB. Tests 12 / 12b.

## Secrets

Generated by `scripts/init-secrets.sh` into `/srv/spark-ai-hub/config/secrets` (mode 700/600, outside Git), mounted as
Docker secrets. The HF token is stored Fernet-encrypted in Postgres and never returned by the API. Logs pass through a
redaction processor (`hf_…`, `sah-…`, bearer tokens, passwords) — unit-tested. The engine-manager redacts tokens in logs it returns.

## Input handling

* **Uploads**: size limits, magic-byte sniffing (images/audio), dataset formats limited to CSV/JSON/JSONL/NPY/NPZ/ZIP;
  `np.load(..., allow_pickle=False)`; ZIP extraction rejects absolute paths, `..`, symlinks, non-images, and bounds
  file count/size (zip-slip unit test). Filenames sanitised.
* **Unsafe deserialisation**: pickle checkpoints (`.pt .pth .ckpt .bin .pkl .joblib .h5 .keras`) are rejected for
  custom models (test 04b); weights are loaded only with safetensors; HF downloads skip pickle files when safetensors exist.
* **Path traversal**: `safe_join` for artifact files; engine-manager validates vLLM model paths with a strict regex;
  ML worker only accepts paths under its read-only mounts.
* **Command injection**: no shell is used with user input; subprocesses use argument lists (pg_dump/pg_restore only).
* **SSRF**: the backend only contacts Hugging Face via `huggingface_hub` with regex-validated repo ids; no user-supplied URLs are fetched.
* **ComfyUI workflows**: users cannot upload workflows; only registered templates with validated parameters run.

## Code execution & containers

* HF custom code (`auto_map`, `*.py`) is flagged; `trust_remote_code` is passed to vLLM only after explicit admin approval
  per model, and then runs inside the `sah-vllm` container (no egress, read-only weights, no-new-privileges).
* Scientific adapters are code shipped with the hub; uploaded artifacts are data. The ML worker runs as uid 1000,
  `cap_drop: ALL`, no egress, read-only models/datasets.
* Docker socket: only `engine-manager` (uid 1000 + docker group, cap_drop ALL, internal network, bearer token) holds it.
  It exposes typed operations for 3 engine names and 1 restartable service; no generic Docker API, image, mount or
  command parameters. **Residual risk**: docker-group access is root-equivalent on the host if the component is compromised.
* Control-plane containers run as uid 1000 with `no-new-privileges` and `cap_drop: ALL` (backend, worker, monitor,
  frontend). Exceptions: postgres/redis/caddy official images; Ollama runs as uid 1000 but with GPU; the NGC vLLM image runs as root inside its container.

## Privacy

Prompts/responses are **not** stored in shared logs; API usage records only metadata (model, tokens, latency, status).
Content logging exists as an admin setting, **off by default**. Playground conversations are private per user.

## Resource exhaustion

Per-role/user policies: concurrent jobs, queued jobs, storage quota, API rpm, monthly tokens, video permission. Scheduler
reservations prevent oversubscription of unified memory (test 14b); GPU-heavy jobs are serialised; uploads are size-bounded.

## Backups

Backups contain the DB (password hashes, key digests, encrypted HF token) and optional user data; stored under
`/srv/spark-ai-hub/backups` (owner-only). Secrets are excluded and must be backed up separately. Off-host copies should be
encrypted at rest by the destination.

## Unresolved / accepted risks

1. Pre-existing **VNC on 0.0.0.0:5902** on a public university address (not part of this project) — verify ufw rules.
2. engine-manager docker-group access is root-equivalent (mitigated, not eliminated).
3. NGC vLLM container runs as root inside; a malicious approved `trust_remote_code` model could attack the GPU driver
   surface. Only approve remote code from trusted publishers.
4. No container image CVE scan and no npm/pip vulnerability audit were performed in this iteration.
5. No OIDC/SSO; no 2FA.
6. Benchmark results (metrics and the shared infrastructure description) are visible to all users; outputs only to the owner.
7. Admin users can read the diagnostic bundle (logs are redacted, but contain request paths and usernames).
